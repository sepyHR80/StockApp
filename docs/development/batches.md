# Dependency-aware work batches

This is an execution map for the [roadmap](roadmap.md), not a replacement for its issue specifications. Phase A is the approved architecture/tooling scope; B–F are future work requiring the appropriate product and operational authorization. This map does not authorize paid infrastructure, model training, or publication of real data. PR [#5](https://github.com/sepyHR80/StockApp/pull/5) remains a native UI prerequisite; verify its current status and base before dispatch.

Assign each implementation issue to GPT-6.1 Terra before work starts. The parent supervises, reviews each issue against its own acceptance criteria and evidence, and verifies each dependency before it is used. Items within a row run in the listed order when one depends on another; grouping does not waive issue-level review. The parent owns the roadmap, verification and issue-status updates after checking evidence. Keep GitHub reports limited to repository/thread facts; never include account details, secrets or private exports.

Use at most three subagents: one heavy worker and read-only review/documentation agents. The parent schedules the single heavy slot across all agents, checks workloads, RAM, swap, Docker and normal memory pressure first, and follows [local limits](../../AGENTS.md#local-resource-limits) and the [runbook](workflow.md). Run focused checks sequentially and preserve caches and volumes. Each exit below also requires the specific issue's full criteria, commands, results and tested commit; human review and required checks precede merge.
