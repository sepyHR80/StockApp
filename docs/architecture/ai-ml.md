# Analysis, inference and research

For closes ordered by trading session, v1 cumulative price return is `last / first - 1`. Daily simple returns are `close[t] / close[t-1] - 1`. Volatility is the sample standard deviation of those returns multiplied by the square root of 252 for US equities or 365 for crypto. Maximum drawdown is the largest positive `1 - close / running_peak`. Use a versioned calculation and serialize dimensionless decimal fractions. Require three completed closes and complete coverage. Persist requested and effective dates, sample size, adjustment basis, missing dates, source and snapshot. Recompute a small hand-calculated fixture in tests.

Job flow is `queued → running → succeeded | failed`. A retryable running job with an expired lease can return to queued. Claim atomically, use a short lease with a unique attempt token, commit results only for the current attempt, and cap attempts at three. Each job records a safe failure code. Metrics become available independently of optional explanation states `disabled | pending | succeeded | unavailable`. A failed model call preserves metrics. Poll using bounded backoff. Reuse an idempotency key only with the same canonical request, scoped to the owner or demo. Return 409 if its request changes. The same key returns the same job even after snapshot refresh.

Runtime routing is explicit environment configuration. Start with metrics only and allow a configured local, hosted API or dedicated cloud inference adapter after evaluation. Keep client packages free of provider secrets. Supply only structured analysis inputs and immutable evidence IDs. Ask for short structured claims with referenced evidence, validate referenced IDs and numeric consistency and suppress outputs that fail checks. Treat market source text and user text as data. Generated explanations receive no secrets, private identifiers, operational tools or ability to place trades. Never silently forward a personal payload from local inference to an external endpoint. Record model revision, prompt revision, latency, timeout and usage. Apply timeout, token limits, request quotas and a circuit breaker before enabling a paid route. Keep a deterministic summary available during failure or rollback.

## Cancellation and deadlines

Assign a wall-clock deadline when a job is queued. Cap leases and external request timeouts at the remaining budget. Once the deadline passes, stop retries and record `deadline_exceeded`. An accepted cancellation stops queued work immediately and signals running work to abort. Fence abandoned attempts with the attempt token so a late result cannot replace terminal state. Use the existing failed state with the safe code `cancelled` when deterministic work is unfinished. If metrics are already committed and the explanation is pending, preserve the succeeded metrics and mark the explanation unavailable. A fully completed job is unchanged; cancellation and completion race by their first committed outcome. Personal cancellation is owner-scoped and idempotent; missing or another owner's job returns 404. Public demo jobs have no anonymous cancellation endpoint. On shutdown, stop accepting work and request cancellation before the process exits. An interrupted lease can be reclaimed only before the job deadline.

## Research protocol

Use a separate process and environment for data preparation, training and evaluation. Freeze a manifest with source, rights, version, checksums, extraction code, universe criteria, adjustment basis, timestamp and available-as-of rules. Include delisted assets when making historical universe claims. Lag inputs to their actual availability and purge overlap between feature/label windows at split boundaries. Fit every transform inside each training fold. Use chronological train and validation windows, iterate with walk-forward validation, then evaluate once on a held-out future window. Treat evaluation on a revised dataset as a new experiment.

Pre-register the prediction horizon, primary metric, baselines, minimum promotion threshold and failure slices. Use naive recent-price or zero-return baselines for forecasts and the deterministic summary for explanations. For forecasts report error by window and asset, quantify uncertainty and include realistic costs for any trading simulation. For explanations measure numeric fidelity, evidence coverage and abstention. Give each run a commit, seed, dependency and hardware inventory, split boundaries, artifact hash, timings and costs. Default to local evaluation and one bounded smoke run. Specify maximum runtime, accelerator hours, API usage and spend before expanding a run. Require explicit budget authorization before paid compute.

Promote only a reproducible version that improves its declared primary baseline and passes grounding, privacy, latency and cost requirements for the intended route. Pin the approved artifact hash with a reviewer decision and keep the previous route ready for rollback. Shadow evaluation can precede limited exposure. Revert to the deterministic summary on regression. Evaluate Android LiteRT only after quantization fidelity, p95 latency, memory, power, APK impact and output parity are measured on named real devices against the approved runtime.
